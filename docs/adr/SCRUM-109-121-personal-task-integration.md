# 담당 업무와 개인 일정·업무일지 연동

상태: Draft · 기준: SCRUM-109 / FR-TSK-01, SCRUM-121 / FR-PSN-03 · 검토일: 2026-11-24

## 배경과 결정

담당 업무 기간을 personal_events에 복제하면 재배정·기간 수정·삭제 때 동기화 누락이 생긴다. 새 GET /api/me/calendar는 개인 일정과 현재 담당 업무를 UNION 조회한다. 기존 /api/me/events 계약을 유지한다. TASK 항목은 WBS 원본 API로 수정한다. 한국 달력의 시작일 00:00부터 종료일 다음 날 00:00까지를 UTC 시각으로 반환한다. 완료 업무도 조회하며, 취소 프로젝트·비멤버·비활성 기능은 제외한다. 시스템 관리자에게 프로젝트 업무를 반환하지 않는다.

기존 worklogs.content는 개인 날짜별 메모로 유지한다. 연결 업무마다 worklog_tasks.content를 별도로 저장하고 PM에게는 해당 프로젝트의 연결 항목만 반환한다. 한 날짜에 여러 프로젝트를 기록해도 다른 프로젝트 내용과 개인 메모를 노출하지 않는다. 기존 본문 전체를 PM에게 공개하는 방안은 권한 범위를 넘으므로 채택하지 않는다.

## 트랜잭션과 재전송

한 요청에서 한 업무만 변경한다. 프로젝트 행 잠금 → 사용자 행 잠금 → 날짜별 노트·업무 연결 조회 → 낙관적 버전 검증 → 업무 진척/완료·상위 가중 집계·이력·업무일지 저장을 한 트랜잭션으로 처리한다. 실패하면 새 날짜별 노트 생성까지 롤백한다. 업무일지와 동일한 값의 재전송은 현재 업무 진척을 다시 덮어쓰지 않는다. 소요 시간은 분 단위의 해당 날짜 입력값으로 교체하며 누적 덧셈하지 않는다.

완료 입력은 progress=100을 요구한다. 기존 업무 재개는 칸반 API로 수행한다. 하위 업무가 있는 상위 업무에 직접 진척을 입력할 수 없다. 프로젝트·단계 집계는 기존 진척률 조회 로직을 유지한다.

## 보관과 삭제

업무일지 연결은 업무 FK를 가지며 연결된 업무 삭제는 WBS_TASK_IN_USE(409)로 차단한다. 개인 일정·업무일지 삭제 정책은 기존 보류 결정을 유지한다. 로그 보관 정리는 error_logs만 대상으로 하며 audit_logs·login_history 정리를 완료했다고 주장하지 않는다.

## 배포·복구

V19는 새 연결 테이블과 조회 인덱스를 추가한다. 기존 V1~V18은 수정하지 않는다. 마이그레이션 후 새 서버를 배포한다. 구버전 API는 개인 메모 계약을 계속 사용할 수 있다. 업무일지 연결 활성화 후 구버전으로 되돌리면 구버전 업무 삭제가 FK로 거부될 수 있으므로 신규 연결 API를 중지하고 roll-forward한다. 연결 데이터를 지워 구버전 삭제를 허용하지 않는다.

## 검증

권한(본인·PM·비멤버·경영진), 동일 요청 재전송, 낙관적 잠금 실패 롤백, 부모 가중 진척, 완료 상태, 재배정 즉시 반영, UTC/한국 자정 경계를 자동 테스트한다. FE는 이번 작업 범위 밖이다.
