## 1. 기준과 적용 범위

기준은 [요구사항명세 최종안: 전사관리](https://jnu-team-aaptc1y6.atlassian.net/wiki/spaces/CoreviaAI/pages/8126909)의 3.3 권한 매트릭스·4.13·5장이다. [DAY(1117) 회의록](https://jnu-team-aaptc1y6.atlassian.net/wiki/spaces/CoreviaAI/pages/19333121)의 개발 규칙과 테마 피드백을 반영한다. 프로젝트 루트 `PROJECT.md`, `development-guidelines/` 원본을 작업마다 읽는다. 본 문서가 상위 가이드라인의 MUST를 완화하지 않는다.

공통 코드·다국어는 MVP 필수다. 테마 **적용 규칙**은 NFR-20 필수이며, 사용자 테마 선택 기능 자체(FR-ADM-12)는 S다. 이 문서만으로 테마 선택 UI·설정 저장 API·테마 종류를 구현 완료로 간주하지 않는다. 흑백 테마는 검토 대상이며 승인된 제공 목록이 아니다.

이 변경의 기준인 원격 `develop` 커밋 `6d39260`에는 공통 코드·다국어 런타임과 FE 화면이 없다. 아래 API는 연결할 팀 명세이며 해당 기능 반영 후 사용한다. SCRUM-168·169가 반영되기 전 임시 코드 목록·번역 사전을 화면에 복제하지 않는다. FE 저장소 적용과 실제 화면 검수는 해당 저장소 변경에서 증거를 남긴다.

## 2. 공통 코드

- 화면 선택지·표시 순서·사용 여부는 [02-3. 공통 코드](https://jnu-team-aaptc1y6.atlassian.net/wiki/spaces/CoreviaAI/pages/21495920)의 `GET /api/codes/{groupCode}` 결과를 사용한다. component별로 상태 배열이나 코드→표시 문구 사전을 만들지 않는다.
- 코드 그룹은 `RISK_LEVEL`, `TASK_STATUS`, `REQUEST_RESULT`, `PROJECT_STATUS`다. `TASK_STATUS` 계약은 `TODO`, `IN_PROGRESS`, `REVIEW`, `DONE`이며 도메인의 `WbsTaskStatus`와 일치시킨다. 코드 값을 표시 텍스트로 사용하거나 한국어·영어 문구로 상태를 비교하지 않는다.
- 코드의 `code`와 `labelKey`는 고정이다. 그룹은 마이그레이션으로 추가하며 기존 코드 값의 변경·삭제 API를 만들지 않는다. 표시 문구는 다국어 라벨에서 수정한다.
- 코드의 `labelKey`는 `code.<GROUP>.<CODE>`, 그룹은 `codeGroup.<GROUP>` 형식이다. 화면은 응답의 `labelKey`를 다국어 리소스에서 해석한다. 코드 목록은 API가 정한 `sortOrder`를 따른다.
- 사용 안 함 코드는 새 선택지에서 제외한다. 기존 업무 데이터의 상태를 다른 값으로 자동 치환하지 않는다. 이미 저장된 값의 표시·전환 가능 여부는 해당 기능 계약과 함께 검수한다.
- BE의 enum·정책·요청 검증은 고정된 업무 계약이다. 이를 코드 테이블의 표시값으로 대체하지 않는다. FE의 조건 분기가 필요하면 공용 계약 타입·상수를 참조하고 component마다 문자열 리터럴을 반복하지 않는다. 알 수 없는 코드가 오면 승인된 공통 오류 UI로 처리하며 허용 상태·권한을 추측하지 않는다.
- 권한 검증은 서버의 공통 인가 모듈에서 수행한다. 코드 조회 성공을 업무 상태 변경 권한으로 사용하지 않는다. 코드 관리 C·U·D 권한은 3.3 기준 시스템 관리자만 갖는다.

## 3. 다국어 라벨

- 메뉴·버튼·상태·알림·관리자 화면·로딩·빈 상태·오류 안내·placeholder·접근 가능한 이름까지 라벨 키를 사용한다. component에 한국어·영어·번체 중국어 문구나 언어별 객체를 넣지 않는다. 공용 상수로 문구를 옮기는 것도 DB 라벨을 대신하지 못한다.
- [02-4. 다국어 라벨](https://jnu-team-aaptc1y6.atlassian.net/wiki/spaces/CoreviaAI/pages/21495939)의 `GET /api/i18n/labels`를 통해 표시한다. 지원 언어는 `ko`, `en`, `zh-TW`다. 표시 언어 우선순위는 `lang` → `Accept-Language` → `ko`이며 사용자 설정·해외법인 기본값은 FE가 요청 언어로 전달한다. 현재 계약에는 사용자별 언어 DB 저장이 없다.
- 영어·번체 중국어 번역 누락은 서버가 한국어로 대체한다. 한국어는 필수다. 라벨 키 자체가 없으면 화면 코드에 문구 fallback을 추가하지 말고 누락을 수정한다. 키 누락·조회 실패 상태는 공통 국제화 경계에서 처리하고 키·진단 정보를 운영 검수에 남긴다. 개인정보·입력 원문은 기록하지 않는다.
- 라벨은 텍스트로 출력한다. HTML로 해석하거나 실행 가능한 template로 사용하지 않는다. 라벨 키는 고정이며 변경·삭제 API가 없다. 시스템 관리자만 문구를 등록·수정하고 변경 이력을 남긴다.
- 서버는 캐시하지 않는 명세다. FE는 화면 진입·언어 전환 때 라벨 묶음을 다시 받아 표시한다. 관리자 수정 후 다음 조회부터 반영되어야 하며, 빌드 산출물·영구 browser cache에 문구를 고정하지 않는다. 재배포 없는 반영이 실시간 push를 의미하지는 않는다.
- 업무 제목·사용자 작성 내용·이름은 사용자 데이터로 취급하고 임의로 번역하지 않는다. 날짜·숫자는 locale API로 표시한다. 화면용 문장을 조각별 문자열 결합으로 만들지 않는다. 현재 라벨 계약에 없는 보간·복수형 기능이 필요하면 계약을 먼저 명세하고 구현한다.
- 기존 BE 오류 응답 계약과 `ErrorCode`를 지킨다. 이 규칙을 이유로 오류 응답 형식·상태 코드·메시지 계약을 일괄 변경하지 않는다. FE 오류 문구는 공용 오류 변환 경계에서 라벨과 연결하고 API 상세·stack trace를 그대로 출력하지 않는다.

## 4. 테마와 디자인 토큰

- 색상·typography·spacing·size·radius·elevation·motion은 승인된 공통 디자인 시스템 token을 참조한다. 색상은 배경·본문·경계·위험처럼 의미를 기준으로 연결하고 개별 화면에서 임의 색상·테마별 삼항식을 반복하지 않는다. token 이름과 실제 값은 디자인 시스템에서 정의한다.
- 테마 선택이 구현되면 공통 소유자 한 곳에서 전 화면에 적용한다. 사용자 선택은 재로그인 후 유지되어야 한다. 저장 위치·서버 API·허용 테마 ID는 FR-ADM-12 구현에서 확정하고, 브라우저 저장소에 비밀값을 넣지 않는다.
- 모든 제공 테마에서 상태는 라벨 텍스트와 아이콘을 함께 사용한다. 위험·지연·완료를 색상만으로 구분하지 않는다. 본문 명암비 4.5:1 이상(큰 글자 3:1), 보이는 focus·키보드 조작·200% 확대와 reduced motion을 검수한다.
- 상태 코드→의미 token·아이콘 대응은 공용 표현 경계 한 곳에서 관리한다. 대응이 없는 새 코드는 특정 정상 상태로 간주하지 않는다. 테마가 인가·상태 전이·업무 데이터에 영향을 주어서는 안 된다.

## 7. PR 완료 기준과 검증 증거

`.github/pull_request_template.md`의 NFR-20 항목을 모든 기능 변경에서 확인한다. UI가 있으면 **화면 코드 내 하드코딩 문구·상태값 0건**이 완료 기준이다. 예외를 허용하는 체크리스트가 아니다. API 계약 enum·라벨 키·사용자 데이터·디자인 시스템 token 정의는 화면 표시값 하드코딩과 구별한다.

1. 변경한 화면뿐 아니라 참조한 공통 component·오류·알림·접근성 이름의 전체 경로를 검수한다. 화면 코드의 literal·상태 배열·문구 매핑·언어별 객체·직접 색상과 조건 분기를 검색하고 모든 후보의 처리 결과를 남긴다. 영어·숫자 문구도 포함한다. 단순 한글 검색 결과가 없다는 이유로 통과시키지 않는다.
2. 정적 검색·프로젝트 lint와 코드 리뷰를 함께 사용한다. 해당 FE가 제공하는 실제 lint·component/E2E 명령을 실행하고 명령·대상 커밋·결과를 기록한다. 이 BE 저장소에 존재하지 않는 FE 검사 명령을 성공한 것처럼 적지 않는다.
3. 관리자 문구 변경→다음 조회 반영, `ko/en/zh-TW` 전환, 번역 누락→한국어 fallback, code 값 불변·표시 라벨 변경, 허용되지 않은 상태 저장 거부를 검증한다. UI loading·empty·error·success와 조회 실패·키 누락도 검수한다.
4. 테마 기능 변경 시 전 화면 즉시 반영·재로그인 유지·각 테마의 상태 텍스트/아이콘·명암비·focus를 검증한다. 테마 기능 미구현이면 해당 없음과 그 이유를 기록한다.
5. PR 증거에 `기준 커밋 / 검수 화면·파일 / 검색·lint 명령과 결과 / 남은 후보 0건 / 세 언어·fallback 결과 / 테마·접근성 결과 / 검수자`를 기록한다. UI 코드가 없는 BE 변경은 `화면 코드 없음: 해당 없음`으로 기록하고 FE의 0건 검증 완료로 표현하지 않는다.

이 저장소에서 화면 유무를 확인하는 실제 명령(결과 없음은 화면 검수 완료를 뜻하지 않음):

```text
git ls-files -- '*.tsx' '*.jsx' '*.vue' '*.svelte' '*.html'
git diff --check
```

Java 동작 변경은 저장소 실제 Gradle 검증(`gradlew.bat check bootJar`, Unix는 `./gradlew check bootJar`)을 함께 수행한다. 본 문서와 도구 규칙만 바뀌는 경우는 문서 링크·명세 일치·규칙 로딩 경로·diff 검수를 수행하고 동작 테스트는 해당 없음으로 기록한다.
